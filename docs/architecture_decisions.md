# Architecture Decisions

记录范围：多站点调度原型首版契约。状态标签 `冻结` 表示接口/实验默认边界已固定；`待现场确认` 表示值不能用于工程运行。

## ADR-001：问题边界与假设（2026-11-23，冻结）

- 覆盖 2-4 个站点。示例 ID `site-1`、`site-2` 仅为合成标识，不映射真实地点。部署方必须提供唯一稳定 ID。
- 调度间隔固定 30 分钟。时间戳为区间起点，采用 ISO-8601，必须带 UTC offset；输入另声明 IANA 时区，且 offset 必须与该时区在该日的规则相符。所有站点共享同一严格递增时间轴。
- 预测时域接口参数化为 `prediction_horizon_steps`。典型实验可用 48 步（24 小时），但首版不把 24 小时硬编码为线上事实；业务方仍须确认滚动窗口长度。此选择兼容现有 `ForecastBundle.horizon_hours` 的 24 小时使用方式。
- 站间交换定义为有方向联络线平均有功功率，`from_site -> to_site` 为正方向、对应 `export_limit_kw`；反方向为负、幅值对应 `import_limit_kw`。限额允许 0 表示该方向禁止，`null` 表示未知且阻止求解。首版不内含潮流、电压或损耗模型；损耗未知时填 `null`，不得默认为零并宣称实测。
- 上级并网进口/出口和站点变压器进口/出口限额作为独立配置。未提供的上级/变压器限额可为 `null`，表示未知/未建模；联络线两个方向限额必须显式提供非负数，`null` 会拒绝构造输入。
- 所有功率用 kW，能量用 kWh，SOC/SOH 用 0-1 fraction，价格用 CNY/kWh，时间长度用分钟。EV、基础负荷、购电、储能充电为用电/吸收正数；站点动作 `storage_kw` 正数为放电、负数为充电，联络线按端点方向定义。`price_yuan_per_kwh` 表示发布/计划的 EV 响应零售价；购电、售电及实际 EV 交付结算价分别独立。契约不接受单位猜测或隐式换算。
- 价格档位由外部配置的 `price_levels` 提供且应和既有滚动控制器一致。价格弹性、保留效用、响应功率因子等属于标定参数，不在本 ADR 发明数值。无合法档位时 Agent/协调器应返回 `invalid_config`。
- 服务优先级首版顺序：安全关键/刚性负荷 > 已承诺 EV 最低服务需求 > 可移峰/价格响应 EV；可再生能源优先消纳，剩余可弃电。公平最低服务率是显式站点配置，待业务方确认数值和公平口径。
- 站点额定功率、储能额定能量/功率/效率和初始 SOC/SOH 必须由资产配置/状态输入提供。v1/common-trace 回放以额定名义容量计算 SOC 动态，SOH 单独记录但不折减名义容量；除非新契约版本显式修改。现有单站模型常用 SOC 0.10-0.90、SOH 0.70-1.00，但不是跨站统一设备事实，未传入资产参数时不得据此证明安全。既有 `BatteryState` 可作为 SOH 状态来源。
- `reserve_margin_kwh` 表示 SOC 高于设备 `soc_min` 所对应的可用能量裕度观测，不是新增 SOC 下界；如优化需要保留额外备用量，使用独立配置 `reserve_requirement_kwh`。
- 硬安全约束：站点功率平衡、设备充放电功率及互斥/转换效率约束、SOC/SOH 限值、EV 服务边界、上级变压器限值、联络线有向限额。Agent 请求只代表候选动作，必须经过既有安全投影；任何投影/校验失败不得下发，账本状态保留失败。
- 系统目标按系统总运营成本最小化（或等价净运营价值最大化）定义，分项报告：实际交付能量对应购电/服务收入、未服务惩罚、弃电惩罚、储能转换损耗、储能退化成本、明确计量的网络损耗；并逐站报告服务量与成本，避免总和掩盖站点损害。无现场合同价格/成本时只报告分项物理量与合成权重，不声称真实经济收益。

## ADR-002：版本化 schema 和 API（2026-11-23，契约 v1.0.0）

- Python dataclass 是实现与内部调用契约，`MultiSiteInput.from_dict()` / `to_dict()` 是 JSON 可序列化边界。每条信号包含数值、单位、来源、状态；状态支持 observed/forecast/missing/assumed/stale/invalid。missing 必须为 `value: null`，assumed 必须带说明。禁止缺失静默填零。
- 必填时序信号：PV/风电/负荷/EV 预测、响应价格、SOC、SOH、备用裕度；购电价、售电价、EV 交付价、实测 PV/风电/负荷/EV、并网功率、联络线功率可选，但缺省不等于零，且三种结算价不可互相代替。
- 静态站点字段以具名单位保存 PV/风电额定功率、变压器进出口限额、储能额定能量/功率/充放效率/SOC-SOH 限值、EV 功率上限和最低服务率。未确认字段保持 null。储能 SOC/SOH 时序状态仍须逐时提供。
- 配置形态由协调请求 `config` 承载：`price_levels`、站点资产/初态/负荷优先级/公平最低服务率、上级限额、方法/超时和策略版本。所有物理参数保持具名单位字段；未知参数使用 null 并由具体算法判断能否运行。
- `SiteStrategy.decide(site_id, forecast, state, constraints)` 返回站点候选动作；`Coordinator.coordinate(CoordinationRequest)` 返回 `CoordinationResult`。forecast/state 可直接包装既有 `ForecastBundle` 与 `BatteryState`；适配时必须要求预测步长与实际区间相符，并把半小时 `interval_hours=0.5` 传给 GameCase/安全层。既有 ForecastBundle 的默认零值字段不适用于缺测输入。
- 协调结果为逐时账本记录，至少包含 contract_version、run_id、时间戳、站点/联络线、请求及安全后动作、实测/预测、成本分项、约束残差、来源和运行状态；失败时保留 `status=failed|partial|infeasible|invalid_input` 及 `failure_code`，不伪造成功行。每行及 run metadata 应记录配置/策略/模型版本。
- 契约变更使用 SemVer：破坏性字段/符号变更升主版本；可选字段向后兼容增加升次版本；文档/修正升补丁版本。旧消费者必须拒绝未知主版本。

## 未确认参数、风险与依赖

1. 站点现场 ID、负荷等级及设备台账；上级变压器进口/出口额定值；联络线拓扑、额定值、损耗：均待现场确认。未知时不能做物理可行性结论。
2. 价格档位及币种/税费/结算边界、价格响应参数和需求服务合同：需业务/历史数据标定。合成响应只可作为明确标记的压力测试。
3. 预测窗口长度及其刷新周期待业务确认。契约强制各站共同时间轴和 30 分钟频率；历史 15 分钟数据必须由上游有据聚合并保留来源。
4. common-trace `thermal_limits_verified=false` 时，只能报告热约束未验证，不能声称全部硬约束已通过。v1 主要校验结构、单位、时间与缺失语义，不替代 AC/DC 潮流、安全认证或线上调度审批。
5. 依赖既有 Python 标准库和当前单站模块；不新增包。协调器/优化器、Agent、长时回放器分别由 C/B/D 实现。
