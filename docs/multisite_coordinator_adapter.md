# Centralized coordinator adapter for contract v1

`CentralizedCoordinator.coordinate()` consumes an A-owned `CoordinationRequest` using `src.multisite.contract` v1.0.0. The adapter does not define a replacement wire schema. Every rolling call must provide `config.provenance`, `method`, `price_levels`, `service_gap`, `time_limit_seconds`, and a `sites` mapping whose keys exactly match the input site IDs. Each site policy must provide `soc_terminal`, `reserve_requirement_kwh`, `degradation_per_kwh`, `base_min_fraction`, `base_unserved_cost`, and `ev_unserved_cost`.

The frozen v1 adapter fields are strict: `provenance` contains exactly `data_class` (`synthetic`, `measured`, or `anonymized`) and a non-empty `source`; `service_gap` contains exactly `max_ev_service_fraction_gap`, a finite value in `[0, 1]`; and `method` is `centralized` or `independent`. The service gap is the maximum absolute difference between any two eligible sites' served-EV/requested-EV fractions. Missing fields, extra keys, or unsupported method IDs are rejected. `price_levels` must be unique positive finite prices. `time_limit_seconds` must be finite and non-negative. Site SOC targets/fractions and costs/reserve are validated against the documented domains. The optimizer also retains legacy standalone provenance labels for non-contract synthetic cases.

An optimal result keeps the complete site, tie-line, and system ledger. `metadata.actions[site_id]` is the JSON form of the first-interval candidate `SiteAction`: timestamp from the first interval, response price from that site's input, storage power as discharge minus charge (positive means discharge), and requested EV service in kW. `metadata.tie_line_flows_kw[line_id]` is first-interval forward minus reverse flow; positive means the configured `from_site` to `to_site` direction. The coordinator consumes the response price as an input and does not optimize price elasticity. EV service is the joint optimizer's demand-response target.

Results include `solver_status`, `failure_code`, `model_sha256`, `source_sha256`, `source_revision`, and `config_sha256`; `input_config_sha256` hashes both the input and config for ledger continuity. The source hash covers the adapter, optimizer and shared v1 contract files. `safe_to_dispatch` is always false. Invalid requests return `invalid_input` with no ledger or actions. Solver infeasibility, timeout, and solver errors retain their status and publish no action schedule. An optimal schedule that fails the adapter's numerical checks is returned as `failed` with `constraint_violation`.

The optimizer models transport-power balances, configured device ratings, upstream limits, tie-line ratings and losses, SOC bounds, and the configured service fairness bound. It does not verify AC/DC power flow, voltage, protection, thermal constraints, or field-device compliance. Downstream execution must independently validate and project candidate actions. Synthetic fixtures validate interface behavior only and are not evidence of site performance or electrical safety.
