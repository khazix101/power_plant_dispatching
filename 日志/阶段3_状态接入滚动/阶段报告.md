# 阶段 3 报告：SOH 状态接入算例与滚动控制

## 1. 目的

把阶段 2 的 `BatteryState` 接入 `GameCase` 和 `RollingSFSEController`，使动态 SOH 状态能够影响滚动窗口中的有效储能容量，同时保留旧的标量 `soh_current` 接口。

## 2. 完成内容

- `GameCase` 新增可选 `battery_state`；
- 新增 `effective_capacity_kwh` 属性；
- `RollingSFSEController` 支持传入 `BatteryState`；
- 使用分组状态的可用容量构造滚动调度电池参数；
- `RollingDecision` 增加 `soh_current` 和 `usable_capacity_kwh`；
- 增加 `advance_battery_day()`，用于日终调用阶段 2 的状态转移；
- 保留旧路径：不传 `battery_state` 时，仍使用 `bundle.soh_current`。

## 3. 状态影响验证

单电池、额定容量 1000 kWh 时：

| SOH | 有效容量（kWh） |
|---:|---:|
| 1.00 | 1000 |
| 0.95 | 950 |
| 0.90 | 900 |
| 0.82 | 820 |
| 0.75 | 750 |

结果说明分组 SOH 状态已经进入滚动算例的物理容量参数。

## 4. 测试结果

- 阶段 3 集成测试：3/3 通过；
- 论文测试：4/4 通过；
- 阶段 1 小算例收益保持 415.6579 元，价格和 SOC 轨迹保持不变；
- 编译检查通过。

## 6. 尚未完成的闭环部分

当前阶段已经让 SOH 影响容量，但领导者目标仍使用原有线性吞吐量成本。退化成本和替换成本尚未进入当前均衡求解目标，因此本阶段还不能宣称完成创新点二的完整闭环。

## 7. 下一阶段入口

下一阶段将把统一退化成本接入领导者目标，并实现两种可比较模式：

1. 当前线性吞吐量成本；
2. 基于 SOH 状态和轨迹的边际退化成本。

随后再把日终替换成本和长期累计收益接入滚动评价。
