# 阶段 2 报告：电池状态与退化接口

## 1. 目的

在不改变当前 SFSE 求解结果的前提下，建立动态 SOH 模型所需的统一状态、退化评价和状态转移接口。

## 2. 完成内容

新增：

- `src/battery/state.py`：`BatteryState`，统一暴露 SOH、可用容量、组状态和替换累计成本；
- `src/battery/degradation.py`：`evaluate_daily_degradation`，统一调用现有分组老化模型；
- `src/game/state_transition.py`：`transition_battery_state`，实现“轨迹 → SOH 更新 → 组迁移/退役 → 下一状态”；
- `local/阶段2_状态退化接口/tests/test_state_interfaces.py`：接口测试。

现有 `BatteryGroupManager`、`asset_eval.py` 和当前博弈模型保持兼容，当前 SFSE 尚未接入新状态转移接口。

## 3. 状态转移约定

本阶段将状态边界放在日级：小时轨迹先产生 SOC、储能功率和 DOD，日终统一计算退化；然后更新组 SOH、执行迁移或退役，并把替换成本返回给上层目标函数。这与后续“小时级博弈 + 日级寿命状态”的建模方案一致。

## 4. 测试结果

接口测试 3/3 通过：

1. 退化计算为正且不修改输入状态；
2. 状态转移后 SOH 下降、电池总数守恒；
3. G3 越过退役阈值时产生退役事件。

另外，阶段 1 的论文测试 4/4 和基线冻结测试 3/3 仍保持通过。

```powershell
D:\miniconda3\python.exe -m compileall -q src local/阶段2_状态退化接口/tests
```

## 5. 当前限制

- 新接口目前采用现有组管理器的聚合 SOH，尚未进入 `GameCase` 或领导者优化目标；
- 退化计算仍是日级后处理，尚未形成“价格影响动作、动作影响未来 SOH、未来 SOH 影响当前目标”的求解闭环；
- 现有 `equilibrium.py` 中的线性吞吐量退化成本仍然独立存在。

## 6. 下一阶段入口

下一阶段应将 `BatteryState` 接入 `GameCase` 和滚动控制器，使当前 SOH 至少影响有效容量和边际退化成本；随后再接入跨日替换成本和长期目标。
